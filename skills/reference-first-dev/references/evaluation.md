# Reference Evaluation

Use this rubric to keep recommendations evidence-based. It is a guide, not a substitute for reading the relevant source and license.

| Dimension | Weight | Evidence |
|---|---:|---|
| Technical fit | 30 | Language, framework, runtime, and feature match |
| Maintenance | 25 | Recent releases or commits, issue response, release hygiene |
| Community evidence | 20 | Adoption, independent users, documentation, and ecosystem support |
| License | 15 | Clarity and compatibility of reuse terms |
| Implementation quality | 10 | Tests, boundaries, structure, and operational documentation |

Do not recommend a candidate solely because it has many stars. Mark missing evidence as unknown.

## License rules

- MIT, BSD, ISC, Apache-2.0, and CC0: reuse may be possible, subject to notices and conditions.
- MPL and LGPL: analyze file-level or linking obligations.
- GPL and AGPL: default to design-only reference unless the target project is intentionally compatible.
- No license: do not copy code.

Always preserve required copyright, license, and NOTICE files when adapting code.
