# 笔记模板与学科变体

## 为什么是这七段

七个段落各回答一个**独立**的问题，合起来才是一份"能自学、能复习、能抗遗忘"的笔记。少一段就会出现具体缺陷：

| 段 | 回答的问题 | 缺了会怎样 |
| --- | --- | --- |
| ① 一句话速记 | 这一节到底在说什么？ | 复习时找不到入口，只能重读全文 |
| ② **从约束推导**（= 第一性原理） | 为什么必须是这个结论？ | 只能死背，忘得最快 |
| ③ 核心机制 | 它怎么运作？ | 只会说名词，不会用 |
| ④ **易错与边界**（= 不确定性审计） | 我哪里会想错？结论在什么前提下才成立？ | 考场上/实践中踩已知的坑 |
| ⑤ 现实关联 | 学了有什么用？还成立吗？ | 学成"考试知识"，无法迁移 |
| ⑥ 考点或应用 | 会被怎么考/怎么用？ | 抓不住重点分布 |
| ⑦ 自测 + 关联 | 我真会了吗？与什么相关？ | 假性掌握；知识成为孤岛 |

> **② 与 ④ 是硬性的，不是可选项。** 不管学科是理工还是文史，不管用户是考研还是通读，这两段都必须存在——它们是把"抄目录"变成"能自己推、自己查错"的唯一两段。篇幅可以压，段落不能删。

# X.Y.Z 标题

> [!NOTE] 一句话速记
> 用大白话把本节核心压成一句。看不懂细节时，先回来看这句。

## 从约束推导：为什么必须是它

不给结论，先推结论。四步：

- **硬约束**：物理、逻辑或需求上绕不开的事实。（不同学科从哪找约束，见下方专节）
- **反事实**：如果没有这个机制/结论，会发生什么**具体的坏事**。
- **候选方案与淘汰**：还能怎么做？为什么都不行？
- **结论**：它被"逼"成了现在这个样子。

> [!TIP] 一句话记住本质
> 把推导的结论压成一句可复述的话。

## 核心机制

只写主干。用表格、Mermaid 图或编号步骤，不要长段落。

## 学科变体表（"具体情况具体分析"的落点）

★ 标记的是**需要改名的段落**——其余段落在所有学科里通用。

| 学科 | ★ 第 ⑤ 段名称 | 该段要写什么 | 第 ⑥ 段侧重 |
| --- | --- | --- | --- |
| **理工 / 工科** | **工程现实** | 是否仍在使用、代表实现（具体产品/系统）、是否已被淘汰、对写代码/做工程的意义 | 计算题、推导题、常见陷阱 |
| **基础理科**（数理化生） | **学科意义与现实应用** | 该结论在本学科体系中的位置、与其他结论的依赖关系、现实中的对应现象 | 证明思路、适用条件、反例 |
| **文科 / 社科** | **思想脉络与现实议题** | 该观点在学术史中的位置、谁在反对它、今天的现实争论 | 名词解释、简答、论述框架 |
| **医学 / 生命科学** | **临床意义** | 与哪个疾病/诊断/治疗相关、机制上如何对应、临床上什么时候用得上 | 病例判断、鉴别诊断、指标意义 |
| **语言类** | **语境与用法** | 使用语域（正式/口语）、常见搭配、母语者常犯的错 | 语法辨析、翻译/写作应用 |
| **法律** | **实务应用** | 法条适用条件、典型判例、合规风险与例外 | 法条适用、案例分析 |
| **商科 / 经管** | **商业含义** | 对决策/成本/风险的意味、真实公司或市场中的例子 | 计算（财务/统计）、情境判断 |
| **艺术 / 设计** | **作品与风格脉络** | 代表作品、风格源流、对后来的影响 | 鉴赏要点、术语辨析 |

> 若学科不在表中：把第 ⑤ 段理解为"**这门学问里，这个知识点往外连到哪里**"，并据此起一个贴切的段名。**段名贴切比统一更重要。**

## 第 ② 段：不同学科的"约束"从哪里找

第一性原理在这段的具体动作是同一个：**找出绕不开的约束 → 设想没有它会出什么坏事 → 淘汰其他方案 → 得出它现在的样子**。学科差异只体现在"约束"的来源：

| 学科 | 约束从哪来 | 一句示例（推导链的起点） |
| --- | --- | --- |
| 理工 / 计算机 | 物理定律、硬件成本、逻辑必然性 | "内存比外存贵且小" → 逼出虚拟内存 |
| 基础理科 | 数学公理、实验事实、守恒律 | "能量守恒" → 逼出永动机不可能 |
| 文科 / 社科 | 当时的物质条件、权力结构、技术手段 | "没有印刷术" → 逼出口传经典的特殊形态 |
| 医学 | 人体生理机制、疾病自然史、可操作性 | "血脑屏障存在" → 逼出给药途径的限制 |
| 语言 | 交际需求、发音经济性、歧义成本 | "同音词太多会造成歧义" → 逼出语法标记 |
| 法律 | 立法目的、利益冲突、可执行性 | "法官不能被无限授权" → 逼出罪刑法定 |
| 商科 | 资源稀缺、信息不对称、激励扭曲 | "信息不对称" → 逼出抵押、审计、担保 |

**判据**：写完第 ② 段后自问一句 —— **"如果去掉这个约束，结论会不会就变成另一个样子？"** 会 ⇒ 真推导；不会 ⇒ 你写的是复述。

## 第 ④ 段：不确定性审计必做的五件事

1. **常见误解表**：写出"多数人会怎么想错"，而不是"要小心"。
2. **前提条件**：明确结论只在什么条件下成立（换条件即失效）。
3. **边界与反例**：找出让直觉失效的极端情形。
4. **易混对比**：与最像的那个概念做一句话切割。
5. **存疑标注**：区分"已核实 / 我的推断 / 未知"，并在正文里写出来，让以后的自己知道哪里不能当定论。

> 这五件事对应 `uncertainty-blindspot-audit` 的思路：**先问"我最没把握的是什么"，再把它写下来**。

## 深度三档（篇幅与内容取向）

| 档 | 篇幅参考 | 取向 | 适合 |
| --- | --- | --- | --- |
| 精炼版 | 60–120 行 | 只留骨架、核心结论、易错点 | 突击、二轮复习 |
| **标准版** | 110–160 行 | 七段齐全，推导与实例适度 | 多数场景（默认） |
| 详尽版 | 200 行以上 | 含完整推导、对比表、例题、跨节串联 | 需要深入理解的硬核科目 |

> 篇幅是**与用户对齐过的**参数，不要自行加码。宁可在某几篇里加深，也不要整体超长（超长直接摧毁"可快速复习"这个核心价值）。
>
> **压篇幅时先砍 ③ 的展开与 ⑥ 的题量，不要砍 ② 和 ④。** 精炼版里这两段可以缩到 3–5 行，但必须在。

## 好写法 vs 坏写法

### 第 ② 段（从约束推导）

**坏**（只是换个说法复述结论）：

> 硬约束：需要虚拟内存。结论：所以有虚拟内存。

**好**（真的在推）：

> **硬约束**：物理内存装不下所有程序，且内存比外存贵得多、小得多。
> **反事实**：若必须全部装入才能运行 —— 程序规模被物理内存硬性卡死，大程序永远无法运行。
> **淘汰**：整体换出（粒度粗、I/O 量大）不行；手工分段（要求程序员干预）不行。
> **结论**：只能"按需装入 + 换出不用部分"，这就是虚拟内存。

### 第 ④ 段（易错与边界）

**坏**（写正确的废话）：

> 注意不要记错。

**好**（写出**具体的误判**与**前提条件**）：

> | 常见误解 | 实际情况 |
> | --- | --- |
> | 并发需要多核 | 错。单核靠时间片交替就能并发；并行才需要多核 |
> **前提条件**：以上针对"单机 + 共享同一硬件"。
> **反例**：并行必然是并发，反之不成立。

### 第 ⑦ 段（自测）

- 问题要**指向推导或判断**，不要考名词背诵（"什么是 X"最没价值）。
- 优先问：换个场景还成立吗？如果去掉某个条件会怎样？A 与 B 的本质区别？
- 答案用标准 HTML 折叠，**不要用某个工具私有的折叠语法**（见 `markdown-compat.md`）。

## 反模式清单

| 反模式 | 后果 |
| --- | --- |
| 七段变成"七个小标题 + 一句话" | 形式齐全但无信息量 |
| 第 ② 段写成"为什么需要它"的空话 | 没有推导链，等于没写 |
| 第 ④ 段写成"注意别记错" | 没有可核对的内容，等于没写 |
| 通篇长段落，无表格无图 | 无法扫读，复习效率归零 |
| 自测题全是名词解释 | 只能检验记忆，不能检验理解 |
| 编造具体实现细节来"显得专业" | 污染知识库，比不写更糟 |
| 全库篇幅长短悬殊（30 行 vs 400 行） | 复习节奏失衡 |
