# 库结构与约定

## 目录结构

```
<库根>/
├── 00-总览/                     ← 索引层（1 个总览 + 每章 1 个章索引）
│   ├── <课程名>.md              ← 总览：地图、用法、约定、进度
│   └── 第N章-<章名>.md          ← 章索引：本节清单（全部链接）+ 高频考点
├── 01-<章名>/                   ← 笔记按章分目录
│   └── <大纲原文标题>.md
├── 02-<章名>/
├── ...
├── 99-模板/
│   └── <笔记模板>.md
├── 99-附件/                     ← 图片等（设为默认附件目录）
└── <其他资料目录>/               ← 如 往年试卷/ 课程作业/ 课程设计/（按用户场景）
```

要点：

- **编号前缀**：章节目录用 `01-`、`02-` 保证按序排列；索引/模板/附件用 `00-` / `99-` 排到两端。
- **笔记文件名 = 大纲原文标题**，不做规范化。
- **原始素材（截图、PDF）放在库外**（父目录）或库内但排除索引——避免污染图谱。
- 若用户已有仓库：**优先新建独立库**，除非用户明确要求并入。并入时也只在库内新建章节目录，不动既有内容。

## 索引层（不可省）

**没有索引层的笔记库 = 信息坟场。** 必须有两层：

1. **总览页**：课程地图（每章几项 + 索引链接）、每篇笔记的固定段落说明、**按使用场景的阅读路径**（跟课/复习/冲刺/查概念）、环境说明、进度清单。
2. **章索引页**：本章定位、知识主线（一段小图或箭头串）、**本节清单表格（全部笔记的链接）**、高频考点、上下章导航。

章索引页在笔记尚未写完时**先列全部链接**——未解析的链接在 Obsidian 里显示为暗淡状态，正好当进度看板。

## frontmatter 约定

```yaml
---
title: "X.Y.Z 标题"
chapter: 3              # 章号，便于后续用 Dataview 之类聚合
chapter_name: 内存管理
section: "3.1"
order: 12               # 全库序号
tags: [<学科>, <章主题>]
aliases: [别名1, 别名2]   # 别名很有价值：搜"别名"也能命中
source: <大纲来源>
type: 课程笔记
status: 待复习
created: 2026-01-01
---
```

- 字段用**少的、能聚合的**：章号、序号、标签、别名足够。
- `status` 便于复习流程（待复习 / 已复习 / 存疑）。
- **正文不依赖任何插件**：笔记在无插件环境下也要能正常阅读，插件只做增强。

## 插件处理

用户已有仓库时，插件可以复用，但：

1. **只从用户已用的仓库复制**（`cp -r 源/.obsidian/plugins/. 目标/.obsidian/plugins/`），并复制 `community-plugins.json`；
2. 复制**前**记录源库状态，复制**后**验证源库未被改动（用 mtime 或哈希对比）并如实报告；
3. 检查复制过来的 `data.json` 里有没有写死的绝对路径/凭据，必要时清理；
4. **不要因为装了插件就让笔记依赖它**。模板文件应是纯 Markdown。

## 库外的既有知识库：只读纪律

- 需要学风格、抄模板、复制插件时：**只读**。
- 任何写操作（包括"顺手改个错别字"）都要先获得明确授权。
- 完成后给出**未被改动的证据**（例如"近 3 小时内该库无文件变更"，并说明期间该库自身的程序活动可能产生的改动，别把别的进程的改动误算在自己头上）。

## 规模与交付节奏

| 项数 | 建议节奏 |
| --- | --- |
| < 20 项 | 一次做完；仍先给 3–5 篇样板 |
| 20–80 项 | 先 1 章样板 → 确认 → 分章批量 |
| > 80 项 | 先 1 章样板 → 确认 → 分章批量，**每章后跑校验**；必要时分多个回合 |

## 命名与链接

- 文件名含 `+`、中文括号、`-`、空格都可以；**唯一要避开的是路径分隔符**（`/`、`\`），必要时用 `-` 或 `I-O` 这类写法替代，并在索引说明。
- 双链目标必须与文件名**逐字符一致**（含空格、全角括号）。
- 改文件名后要全库改链——用 `obsidian-cli move` 之类能自动更新链接的工具（见 `obsidian` skill），或改完立即跑死链校验。

## 进度与记忆

- 库内的进度写在总览页（用户可见）。
- **长期约定**（模板结构、语法白名单、目录归属、只读禁区）写进项目的常驻记忆或规则文件，**不要只写在日志里**——日志会被压缩，约束会丢。
