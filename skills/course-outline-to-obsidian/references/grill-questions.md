# 阶段 1 追问清单

来源：`grill-me` 的方法论（先列分支 → 给自己的推荐 → 再问 → 一次解决一支）+ 实战沉淀。

## 核心纪律

1. **先列分支，再提问。** 把顶层决策分支列出来（3–6 条），标出哪些你自己定、哪些必须问。让用户看到全景，而不是面对零散问题。
2. **每个问题先给自己的推荐答案**，并说明理由。用户看到推荐后往往只需回一个"可以"。
3. **一次只推进一支**（或把强相关的 2–3 问合并成一批），不要一口气抛出十个问题。
4. **能自己查的绝不问。** 文件里能看到的一律自己看（见 SKILL.md 阶段 0）。
5. **只问三类**：不可判定歧义 / 权威冲突 / 缺失授权。
6. **技术方案一律自己定**：目录结构、命名、frontmatter 字段、模板段落、交付批次、语法选择——自己推 + 说明理由 + 留痕。

## 通常只需要问的 3 个问题

### Q1：放在哪里？（缺失授权/环境事实）

- **背景**：给出你**实际查到**的事实与数字（例如"我查到你有 4 个仓库：A/B/C/D，其中 C 当前处于打开状态；另有目录 E 下只有素材没有仓库"）。
- **推荐项 + 理由**：推荐建在归属最明确的位置，并说明为什么不建议动既有仓库。
- **替代路线后果**：放进既有仓库会怎样（污染图谱/与既有插件耦合/插件模板冲突）；单独新建会怎样（要另配环境）。
- **影响范围**：会新建哪些目录、哪些既有文件**不受影响**、有没有副作用。
- **未答复处置**：默认建在"项目目录下新建独立库"，且不动既有仓库。

### Q2：主要用途与定位？（用户偏好，无法推断）

- **背景**：说明这个答案会改变什么（同一知识点在"应试"与"理解"两种定位下写法完全不同，举例说明）。
- **选项建议**：① 应试+理解兼顾（推荐）② 应试优先（要口诀、题型、易错）③ 理解优先（要推导、图示、来龙去脉）。
- **未答复处置**：默认"兼顾"，并在样板提交时请用户校准。

### Q3：单篇篇幅与深度？（用户偏好，直接决定工作量与复习手感）

- **背景**：给出**具体数字**（例如"全库 86 篇；每篇 150 行约 1.3 万行"）。
- **选项建议**：① 标准版（推荐，给出行数区间）② 精炼版（给出区间，说明适合突击）③ 详尽版（给出区间，说明产出最慢）。
- **未答复处置**：默认标准版。

## 其余可在书面说明中"一并告知"的决策（不问，只告知）

以下全部自己定，但在回复里用一两行说明，给用户否决机会：

- 文件名规范（**沿用大纲原文**）；
- frontmatter 字段设计；
- 目录结构（章节目录 + 索引目录 + 模板目录 + 附件目录）；
- 索引层设计（总览 + 每章索引）；
- 语法约定（只用跨工具通用语法）；
- 交付节奏（先样板、后分章批量）；
- 校验方式（跑脚本，报告证据）。

## 反模式（提问时最容易犯的错）

| 反模式 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 问"先做哪一章" | 执行顺序由你定，用户不关心 | 自己定：按大纲顺序 |
| 问"文件名要不要加编号" | 技术方案，可逆 | 自己定并留痕 |
| 问"用 Mermaid 还是表格" | 技术方案 | 自己定；需要时举例让用户看效果 |
| 把"我查不到"包装成问题 | 可能只是没查全（如只查了一层配置） | 穷尽只读手段后再判断 |
| 一次抛 10 个问题 | 用户注意力被打散 | 合并为 2–3 个，其余写成"我的默认做法" |
| 问"你要不要我帮你做" | 用户已经要求了 | 直接做，只在不可逆处确认 |

## 自检三问（发问前必过）

1. 这个问题**是否已被现有规则或文件回答**？是 → 按规则执行，不问。
2. 这个决定**是否可逆且不改变决策语义**？是 → 自己定并留痕，不问。
3. 如果我错了，代价是**返工**还是**不可逆损失**？返工 → 自己定；不可逆或策略偏离 → 问。

## 五要素（缺一项不得发出）

| # | 要素 | 要求 |
| --- | --- | --- |
| 1 | 背景 | 发生了什么、怎么查出来的，**须含实际数字** |
| 2 | 推荐项 | 附理由 |
| 3 | 替代路线后果 | 不采纳会怎样；各选项的代价 |
| 4 | 影响范围 | 会改哪些文件 / 哪些不受影响 / **副作用** |
| 5 | 未答复处置 | 用户不回答时默认怎么做 |
