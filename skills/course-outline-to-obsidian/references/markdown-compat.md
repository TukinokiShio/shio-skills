# 跨工具 Markdown 语法约定

目标：同一份笔记在 **Obsidian、Typora、VS Code、GitHub、通用预览器**里都能正常显示。宁可少一点花哨，也不要"换个工具就变成乱码原文"。

## 白名单（放心用）

| 用途 | 写法 | 兼容情况 |
| --- | --- | --- |
| 提示块 | `> [!NOTE]` / `> [!TIP]` / `> [!IMPORTANT]` / `> [!WARNING]` / `> [!CAUTION]` | **GitHub Alert 的 5 种**。Obsidian 原生认；Typora 1.8+ 认（需在偏好设置里开启 "Github Style Alert"）；GitHub 认 |
| 折叠答案 | `<details><summary>答案</summary>…</details>` | 标准 HTML。Obsidian / Typora / GitHub / VS Code 均支持，**且不依赖任何插件** |
| 图 | ```` ```mermaid ```` | Obsidian、Typora 原生渲染；GitHub 也支持 |
| 表格、任务列表、加粗、行内代码 | 标准 GFM | 通用 |
| 内部链接 | `[[双链]]` | **Obsidian 原生**；导出到别处会退化为普通文本（内容不丢，但不跳转） |
| 属性 | YAML frontmatter | Obsidian 原生；其他工具显示为原文或忽略 |

## 黑名单（不要用）

| 不要用 | 原因 |
| --- | --- |
| `> [!abstract]` / `[!success]` / `[!info]` / `[!todo]` / `[!bug]` 等 | **Obsidian 私有** callout 类型，不在 GitHub Alert 5 种之内。Typora 与通用渲染器会**显示成原文** `[!success]` |
| `> [!NOTE]-` 这类**尾随短横线折叠** | 折叠是 Obsidian 私有扩展。其他工具会显示成 `[!NOTE]-` 原文 |
| 需要插件的语法（Dataview 查询块、Templater 指令）**出现在笔记正文里** | 没装插件的环境会显示成代码块原文。可放在**索引页**作增强，正文不要依赖 |
| 以 `/` 结尾的文件名或含路径分隔符的文件名 | 文件系统层面直接失败 |
| 花括号/尖括号里的自定义占位语法（如 `{{title}}`）出现在成品笔记中 | 会被当字面量显示 |

> 实测教训：`> [!success]- 答案` 在 Obsidian 里是漂亮的绿色可折叠框，但在通用 Markdown 预览器里**就是一行 `[!success]- 答案` 原文**。折叠改用 `<details>` 后，Obsidian 与 Typora 都能折叠。

## `<details>` 的写法要点

1. **与前后内容留空行**，否则部分渲染器会把后面的内容吞进 HTML 块（尤其是后面紧跟 `1.` `2.` 这类编号列表时）。
2. 在编号列表内使用时，保持与列表项相同的缩进。
3. 内容里如果需要 Markdown（表格、列表），**与 `<summary>` 及 `</details>` 之间各留一个空行**。

```markdown
1. 问题？

   <details>
   <summary>答案</summary>

   答案内容（可含 **粗体**、`代码`、表格）。

   </details>

2. 下一题
```

## 双链的取舍

- 笔记以 **Obsidian 为家**时，双链是最大价值（图谱、反链、跳转）。
- 若用户明确说"我还要导出到别处看"，则：
  - 双链仍可用（退化后是纯文本，不影响阅读）；
  - 但**不要**用 `![[嵌入]]` 这类只在 Obsidian 有效的嵌入语法；
  - 重要关联同时在正文里用文字说明一遍（如"详见 3.1.3 节"）。

## 长度与转义注意

- 文件名避免：`\ / : * ? " < > |`（Windows 限制）；全角 `：`、`（）`、`、` 都是安全的。
- 表格里出现 `|` 要转义为 `\|`。
- 代码块里嵌套代码块，用**比内层更多的反引号**包裹（如外层 4 个、内层 3 个），并注意反引号总数为偶数，否则校验脚本会报"围栏不平衡"。

## 校验

`scripts/verify_notes.py` 会自动检查：

- 是否有黑名单 callout 类型残留；
- 代码围栏是否成对；
- `<details>` 与 `</details>` 是否配对；
- 双链是否有死链。

**每次批量产出后跑一次**，不要凭肉眼判断。
